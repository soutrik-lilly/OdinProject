CSS: Cascade, Specificity, Box Model & Units
Why This Day MattersSpecificity conflicts are the #1 source of "why won't this style apply?" bugs. The box model determines rendered dimensions. If you don't understand border-box, your Tailwind classes will behave unexpectedly. These are the rules the browser runs 60 times per second.
TOPIC CHECKLIST
01
Cascade Priority Order!important → inline style → ID selectors → class/attr/pseudo-class → type selectors → universal; when equal specificity: last declared wins; inheritance: some properties inherit (font-family, color) — most don't (padding, border)
02
Specificity: The 0-0-0 Systemthree columns: (IDs, Classes+Attrs+Pseudo, Types); p=0-0-1; .class=0-1-0; #id=1-0-0; p.class=0-1-1; gold standard: never use #id in CSS (nearly impossible to override); never use !important outside @layer utilities
03
Box Model — Draw It From Memorycontent → padding (inherits background) → border → margin (always transparent); collapsing margins: adjacent vertical block margins collapse to the larger value (does NOT happen in Flexbox/Grid)
04
border-box: Always Use Itcontent-box (default): width:200px + padding:20px + border:2px = 244px actual; border-box: width:200px includes padding and border — always what you expect; production rule: *, *::before, *::after { box-sizing: border-box } as the very first CSS rule
05
CSS Units — When to Use Whichpx: borders (1px), box shadows — fixed; rem: ALL font sizes and spacing — relative to root 16px, scales with user font preferences; em: component-internal spacing; %: widths in flow layout; vw/vh: viewport fractions; dvh: dynamic viewport height (accounts for mobile browser chrome — always use dvh instead of vh); ch: 60ch ideal line length; clamp(min, preferred, max)
06
Never px for font-sizepx for fonts breaks browser zoom (accessibility violation — WCAG 1.4.4); always rem for font sizes
07
Modern CSS Reset*, *::before, *::after { box-sizing: border-box }; * { margin: 0 }; body { line-height: 1.5; -webkit-font-smoothing: antialiased }; img, video { display: block; max-width: 100% }; input, button, textarea, select { font: inherit }; p, h1–h6 { overflow-wrap: break-word }

Why This Day MattersEvery Tailwind class like flex, justify-between, items-center is Flexbox. Every chat bubble layout, navbar, sidebar + content split, and tag cloud uses Flexbox. The min-width:0 gotcha will bite you in production — every chat UI hits it.
TOPIC CHECKLIST
01
The Two-Axis Mental Modelmain axis (items flow along) and cross axis (perpendicular); flex-direction:row → main is horizontal, cross is vertical; flex-direction:column → main is vertical, cross is horizontal; justify = main axis alignment; align = cross axis alignment
02
justify-contentflex-start (default), flex-end, center, space-between (gaps between items, no outer gap — most common), space-around, space-evenly
03
align-itemsstretch (default — items fill cross axis), flex-start, flex-end, center (vertical centering when row direction), baseline
04
flex shorthand — The Three Valuesflex: grow shrink basis; flex:1 = 1 1 0% (equal shares from zero); flex:none = 0 0 auto (fixed, no grow/shrink); flex:auto = 1 1 auto (grow and shrink, start from content size); flex:0 0 200px (fixed 200px)
05
gapalways prefer gap over margin-right/bottom on flex items; no outer gap unlike margin
06
flex-wrap:wrapitems wrap to next line; when wrap is set, align-content controls how lines distribute on cross axis (same values as justify-content)
07
The min-width:0 Gotchaflex items have min-width:auto by default — "never narrower than my content"; this prevents text truncation inside flex children; fix: add min-width:0 to the flex child — then overflow:hidden + text-overflow:ellipsis works correctly; THIS IS THE MOST COMMON BUG IN CHAT UIs

TOPIC CHECKLIST
01

Positioning, Z-index, Stacking Contexts, Transitions & Animations
Why This Day MattersPosition:sticky for navbars, absolute for dropdown menus, fixed for modals. The stacking context rule explains z-index:9999 bugs that every developer hits. Transitions and animations are how AgentOS's message slide-in, typing indicator, and streaming cursor look polished.
TOPIC CHECKLIST
01
Position Valuesstatic (default, normal flow); relative (offset without affecting others, creates stacking context); absolute (removed from flow, positioned relative to nearest positioned ancestor); fixed (relative to viewport); sticky (normal flow until scroll threshold, then fixed within parent)
02
Sticky: The Parent Overflow Gotchaposition:sticky silently stops working if any ancestor has overflow:hidden or overflow:auto; the sticky element must be able to scroll relative to its containing block
03
Stacking Contextscreated by: position + z-index (not auto), transform (any), opacity < 1, filter, will-change, isolation:isolate; elements inside a stacking context cannot escape it — z-index:9999 inside a context cannot appear above elements outside it; use isolation:isolate to create a context without side effects
04
GPU Performance Ruleonly animate transform and opacity — GPU-composited, no layout; animating width/height/top/left triggers Layout → Paint → Composite every frame (jank); transform:translateY(-2px) not top:-2px; will-change:transform sparingly (wastes GPU memory if overused)
05
Transitionstransition: property duration timing-function delay; ease-out (slow end — most natural for entries); ease-in (slow start — exits); always apply to base element, not :hover (so transition runs both directions)
06
@keyframes Animationsname a sequence of from/to or 0%/100%; animation-fill-mode:forwards (keep end state); animation-play-state: running/paused (controllable via JS); iteration-count: N or infinite; direction:alternate (ping-pong)
07
Three AgentOS Animationsmessage slide-in: opacity 0 + translateY(12px) → opacity 1 + translateY(0), 200ms ease-out; typing indicator: three dots with staggered animation-delay, translateY bounce, infinite alternate; streaming cursor: opacity 1 → 0, step-end infinite (makes it blink not fade)

Server Components vs Client Components: The Mental Model
Why This Day MattersThe Server Component vs Client Component distinction is the defining mental model of Next.js App Router. Getting it wrong means either shipping too much JS to the browser (Client where Server should be) or losing interactivity (Server where Client should be). This is the concept that trips up most React developers new to Next.js.
TOPIC CHECKLIST
01
Server Components — The Defaultall components in /app are Server Components by default; run on Node.js server (or during build for static); never sent to browser as JS; can: top-level await, read env variables, access database/filesystem, use server Node.js APIs; cannot: useState, useEffect, browser APIs, event handlers, React hooks
02
"use client" Directivemarks file + ALL its imports as Client Components; Client Components render on server once (initial HTML) + hydrate in browser; can use all React hooks and browser APIs; cannot import Server-only modules; "use client" at TOP of file before imports
03
The Composition RuleServer Components CAN import and render Client Components; Client Components CANNOT import Server Components; BUT: Client Components CAN accept Server Components as children prop (passed as JSX); this is how you compose: Server wrapper → Client interactive child → Server content as children
04
Where to Use EachServer: data fetching, access to secrets, static content, large dependencies that don't need interactivity; Client: event handlers, React hooks, browser APIs, interactive UI (forms, modals, dropdowns); default to Server; only add "use client" when you need interactivity
05
Serialization Constraintprops from Server to Client must be serializable (JSON-safe): strings, numbers, booleans, arrays, plain objects; cannot pass: functions, class instances, Dates (convert to ISO strings), Promises — except use() handles Promises
06
use() for Server → Client DataServer Component: const dataPromise = fetchSlowData(); pass as prop to Client; Client: const data = use(dataPromise) inside Suspense; suspends until resolved; keeps the fetch on the server while the Client component handles interactivity

Auth Module — Technical Blueprint

Authentication, Authorization & SSO — What You're Actually Building

Before writing a line of code, understand the precise technical architecture. The concepts below explain what happens, why it happens that way, and where each piece lives in a Next.js + FastAPI stack.

Authentication (AuthN)
Who Are You?

Proving identity — "I am Soutrik." Methods: username+password (credential exchange), SSO (delegate to a trusted identity provider like Google or Microsoft Entra ID). The answer is a verified identity claim, typically a JWT.

Authorization (AuthZ)
What Can You Do?

Granting permissions — "Soutrik is an admin who can delete conversations." Happens AFTER authentication. RBAC: roles (admin, editor, user, viewer) mapped to permissions. Enforced at the API level AND the UI level.

SSO (Single Sign-On)
Delegated Identity

User authenticates once with their Identity Provider (Google, Microsoft Entra ID, Okta) — your app trusts the IdP's verification. No passwords stored in your database. Protocol: OAuth 2.0 + OIDC. Standard for every enterprise and SaaS product.

The Complete SSO Flow — Step by Step
STEP 1–2 · Browser
Initiate

User clicks "Sign in with Google." NextAuth.js redirects to Google's auth endpoint with: client_id, redirect_uri, scope=openid email profile, state (CSRF), code_challenge (PKCE).

STEP 3 · IdP
Authenticate

User enters their Google (or Microsoft) credentials on the IdP's own page. Your app never sees the password. IdP verifies identity internally.

STEP 4–5 · Callback
Code Exchange

IdP redirects back to /api/auth/callback/google with a one-time authorization code. NextAuth.js (server-side) exchanges code + code_verifier (PKCE) + client_secret for tokens at IdP's token endpoint.

STEP 6–7 · Verify
OIDC Validation

NextAuth.js receives an id_token (JWT). It fetches the IdP's public keys from the JWKS endpoint and verifies the id_token's signature cryptographically. Extracts: email, name, provider_id.

STEP 8–10 · Backend
Provision & Issue

NextAuth.js calls FastAPI. Backend finds or creates the user (email as unique key), assigns default role, issues its own JWT (access + refresh tokens). Frontend receives app session. User is in.

Frontend (Next.js) Owns
  • NextAuth.js v5 (Auth.js) — handles the entire OAuth dance: redirect, callback, PKCE, token exchange, JWKS verification, session encryption; never build this yourself
  • Login Page — SSO buttons (Google, Microsoft), email+password form, "or continue with" separator, remember me; uses shadcn/ui components
  • Session Provider — <SessionProvider> wraps app; useSession() in Client Components; getServerSession(auth) in Server Components; auth() in middleware
  • Middleware (middleware.ts) — checks auth for every protected route; checks role for admin routes; redirects to /login with ?from= param; runs on Edge Runtime
  • Permission Components — <CanI action="delete" subject="conversation">: renders children only if user has permission; usePermissions() hook; hide UI for unauthorized actions
  • Auth Callbacks in authConfig — jwt() callback: add role to JWT; session() callback: expose role to useSession(); signIn() callback: call FastAPI to provision user; redirect() callback: post-login destination
Backend (FastAPI) Owns
  • POST /auth/sso — receives verified user info from NextAuth.js; finds or creates user in DB; assigns default role; returns user data + app JWT tokens
  • User Provisioning — first SSO login: INSERT user with email, name, provider, provider_id; subsequent logins: find by provider_id or email; link multiple providers to one account (oauth_accounts table)
  • JWKS Verification (optional) — if verifying IdP tokens directly in FastAPI: fetch public keys from IdP's /.well-known/openid-configuration → jwks_uri; cache the keys; verify signature with python-jose or joserfc
  • Role Management — roles stored in users table; GET /admin/users to list users; PATCH /admin/users/{id}/role to assign roles; only admins can manage roles
  • FastAPI Role Dependencies — require_role("admin"): Depends(get_current_user) + check user.role; require_permission("delete:conversation"): fine-grained permission check; applied per-endpoint
  • Audit Log — login events, role changes, admin actions logged to audit_log table; who did what, when, from what IP; after() API in Next.js or FastAPI background task
Technology Decisions — Why These Tools
NextAuth.js v5 (Auth.js)

The de-facto standard for Next.js auth. Handles OAuth PKCE, JWKS verification, CSRF, session encryption (JWE), database adapters, 40+ providers. Never implement OAuth yourself — the spec is complex and the security surface is large.

OIDC / OAuth 2.0 Providers

Google: easiest setup, works for consumer apps. Microsoft Entra ID (Azure AD): enterprise standard — critical for Lilly BI&A internal tools, uses MSAL. Okta/Auth0: for organizations with custom IdP requirements.

joserfc / python-jose

FastAPI JWT library. joserfc is the modern choice (actively maintained). python-jose works but slower updates. Used for: verifying OIDC id_tokens from the IdP, and signing/verifying your own app JWTs.

Casbin / Custom RBAC

For simple apps: store role in users table, check in Depends(). For complex apps: Casbin policy engine for fine-grained permissions. AgentOS uses simple RBAC: admin/editor/user/viewer roles checked per endpoint.

Hypermedia Stack Module · 4 Days · 16–20 Hours

HTMX + Alpine.js + Tailwind v4 + Jinja2

A complete, self-contained module for the hypermedia-driven stack. This is the Python-engineer-first approach to building UIs — no React, no Node.js, no build step for most workflows. FastAPI serves HTML. HTMX handles server interactions. Alpine.js handles client-only interactivity. Jinja2 templates compose the views. Tailwind styles everything.

The Hypermedia Philosophy
HTML over the Wire

The React stack sends JSON from server to client, then JavaScript builds the DOM. The hypermedia stack sends HTML directly — the server is the source of truth for the UI. HTMX replaces the need for an API layer in most cases.

This is not a step backward. It is a deliberate architectural choice — one that scales well for internal tools, admin dashboards, data-heavy applications, and any context where a Python team owns the full stack without frontend specialists.

When to Use This Stack
✓ Use When
  • Internal tools and admin dashboards
  • CRUD-heavy forms with server validation
  • Python/FastAPI team, no frontend specialist
  • Rapid prototyping — no build step
  • LLM dashboards with streaming responses
  • Data tables with server-side pagination
  • PharmaVigil-class domain tools
✗ Don't Use When
  • Complex real-time multi-user collaboration
  • Mobile-first apps (React Native needed)
  • Offline-first or PWA requirements
  • Very complex client-side state machines
  • Consumer products needing React ecosystem
  • Team already deep in React/Next.js
Stack Role Map — What Each Technology Does
Jinja2
Server Rendering

Renders HTML on the server using Python data. Template inheritance for layouts. Macros for reusable components. Auto-escaping for XSS safety. FastAPI calls TemplateResponse, Jinja2 produces the HTML fragment or full page.

HTMX
Server Interactions

HTML attributes (hx-get, hx-post) that make HTTP requests and swap the response HTML into the DOM. Handles 90% of interactivity — pagination, forms, live search, delete, create — without writing JavaScript.

Alpine.js
Client Interactivity

Handles the UI behaviors HTMX cannot: dropdowns open/close, tabs switch, modals toggle, character counters update, form validation feedback. Tiny reactive state in HTML attributes — no component files, no build step.

Tailwind v4
Styling

Exactly as in the React stack. Via CDN for quick prototypes, or via pytailwindcss for production builds. Utility classes in Jinja2 templates. Dark mode via data-theme attribute toggled by Alpine.js.

Vercel AI SDK v6 Core — useChat, UIMessage Types, Transport Layer & Stream Anatomy
Why This Day Matters The Vercel AI SDK's useChat hook is the foundational streaming primitive for every production LLM chat UI. It manages all message state, handles the streaming protocol, provides abort/resume capabilities, and integrates with your backend over a typed wire format. Without understanding this SDK, you are re-implementing what it already solves — worse. The entire BIA_CATS_AIA_TEMPLATE_UI is built on this SDK as its core dependency.
WHAT YOU WILL LEARN
01
SDK Architecture — What useChat Actually Is The Vercel AI SDK v6 is not a UI component library — it is a streaming state machine. useChat from @ai-sdk/react manages a ChatMessage[] array, handles the SSE stream from your BFF, provides status ('submitted' | 'streaming' | 'ready' | 'error'), and exposes sendMessage, stop, regenerate. The hook talks to your backend via a ChatTransport (default: POST to /api/chat). The wire protocol between SDK and backend is the Vercel UI Message Stream format — not raw SSE, not JSON, a specific newline-delimited format.
02
UIMessage and ChatMessage — The Central Type UIMessage<Metadata, DataTypes> from the ai package is the base message type. In production: type ChatMessage = UIMessage<{createdAt: string}, CustomUIDataTypes> where CustomUIDataTypes is a key-value map of custom data part types. useChat<ChatMessage> — always pass the full type. UIMessagePart<>: the discriminated union of part types ('text', 'reasoning', 'dynamic-tool', 'data-error', etc.); iterate message.parts and switch on part.type to render. DataUIPart<CustomUIDataTypes>: custom data sent via onData callback — used for reasoning steps, cache-hit badges, usage stats.
03
useChat Configuration — Every Option That Matters useChat<ChatMessage>({id, messages: initialMessages, experimental_throttle: 100, generateId: crypto.randomUUID, resume: id !== undefined && messages.length > 0, transport: new ChatTransport({...})}). experimental_throttle: 100 — re-renders at most every 100ms during streaming, prevents O(N) token re-renders on long conversations. generateId: always use crypto.randomUUID() not nanoid() — if your DB column is uuid type, nanoid breaks. resume: true — auto-reconnects to an in-progress stream on mount (for page reload during streaming). id: the thread ID — ties to your backend's checkpointer key.
04
onData, onFinish, onError — The Three Critical Callbacks onData(dataPart: DataUIPart<CustomUIDataTypes>): fires for every custom data part received — reasoning steps, cache-hit badges, usage stats. Store in a Context (DataStreamProvider) so any component can read them. onFinish({isAbort, isDisconnect, isError}): fires when the stream ends; check isDisconnect to retry with resumeStream(); check if last part type was 'finish' to know if it's complete. onError(error): fires on network failures or non-2xx responses; parse the JSON body for structured errors (rate_limit_exceeded, service_unavailable).
05
DefaultChatTransport — Extension Pattern DefaultChatTransport from ai is the base HTTP transport. Extend it to intercept every stream chunk: class ChatTransport<T> extends DefaultChatTransport<T> { protected processResponseStream(stream) { return super.processResponseStream(stream).pipeThrough(new TransformStream({ transform(chunk, ctrl) { onStreamPart?.(chunk); ctrl.enqueue(chunk); } })) } }. Override prepareSendMessagesRequest to customise the request body (add chatId, visibilityType, modelId). Override prepareReconnectToStreamRequest to build the resume GET request with cursor header.
06
The Vercel UI Message Stream Wire Format The SDK sends/receives a newline-delimited format, NOT raw SSE: f:{"messageId":"uuid"}\n (message start), 0:"token text"\n (text delta), 2:[{"type":"reasoning-step","data":{...}}]\n (data part), e:{"finishReason":"stop"}\n (message end), d:{"finishReason":"stop","usage":{...}}\n (stream done). Your BFF uses createUIMessageStream to produce this format and pipeUIMessageStreamToResponse to send it. The browser's fetch reads it with response.body.getReader(). The SDK handles all parsing — you never write a reader in client code.
07
Stream Resume — Cursor Tracking and Reconnect Stream resume allows the browser to reconnect after a network drop and continue receiving the in-progress LLM response. Client side: use useRef to track stream cursor (chunk count) — a ref, not state, because state updates are async and would miss chunks. Increment cursor in onStreamPart. On disconnect (onFinish({isDisconnect:true})): call resumeStream() if the stream was incomplete (last part type !== 'finish'). Limit retries to 3. Server side: GET /api/chat/:id/stream with X-Resume-Stream-Cursor header — returns cached chunks from that cursor index. The cache must be populated during the original stream.

Vercel AI SDK v6 Server-Side — createUIMessageStream, SSE Protocol Translation & BFF Pattern
Why This Day Matters The BFF (Backend-For-Frontend) is the most critical file in this UI. It reads one SSE stream format (Responses API, from FastAPI/LangGraph), transforms it event-by-event, and writes another (Vercel UI Message Stream, to the browser). This dual-protocol translation is the entire job of the Node.js BFF. Without understanding this transformation layer, you cannot build the bridge between your Python agent and your React UI.
WHAT YOU WILL LEARN
01
createUIMessageStream + pipeUIMessageStreamToResponse const stream = createUIMessageStream({ execute: async ({ writer }) => { /* write events */ }, onFinish: async ({ responseMessage }) => { /* save to DB */ } }). The writer is the UI Message Stream writer — call writer.write({type:'text-start', id}), writer.write({type:'text-delta', id, delta}), writer.write({type:'text-end', id}) for text parts. Call writer.write({type:'data-reasoning-step', data:{...}}) for custom data events. Then: pipeUIMessageStreamToResponse({ stream, response: res, consumeSseStream({stream: sseStream}) { cache.storeStream({streamId, chatId, stream: sseStream}) } }). The consumeSseStream callback gives you the SSE-format stream being sent to the browser — store it for resume.
02
Async Generator SSE Parser — parseAgentSSE() Parse the FastAPI/LangGraph SSE stream with an async generator: read chunks from body.getReader(), decode with TextDecoder({stream:true}), split on \n, keep partial last line in buffer (handles TCP packet boundaries), filter for data: prefix, .trim() for \r\n, check for [DONE] sentinel (return from generator), JSON.parse in try/catch (silently skip malformed lines). The generator signature: async function* parseAgentSSE(body: ReadableStream<Uint8Array>): AsyncGenerator<Record<string, unknown>>. Critical: always reader.releaseLock() in finally — failure to release blocks all future reads on that body.
03
Event Type Switch — The Translation Map For each event from parseAgentSSE, switch on event.type: response.output_item.added (message type) → capture messageId, reset messageStarted, detect "cached-" prefix for cache-hit; response.text.delta → first time: writer.write({type:'text-start', id:messageId}), always: writer.write({type:'text-delta', id:messageId, delta:event.delta}); response.output_item.done (message) → if streaming was active: text-end; else synthesise start+delta+end from item.content[0].text (intent_check rejection path); response.output_item.done (function_call) → tool-input-available; (function_call_output) → tool-output-available; response.reasoning_step → data-reasoning-step custom data; error → data-error custom data.
04
Critical SSE Headers — X-Accel-Buffering and Others Set these on res BEFORE calling pipeUIMessageStreamToResponse: res.setHeader('X-Accel-Buffering', 'no') — tells NGINX and Traefik not to buffer the SSE response; without this, the proxy accumulates all tokens and sends them at once at the end — no streaming effect; res.setHeader('Cache-Control', 'no-cache'); res.setHeader('Connection', 'keep-alive'). SWR v2 Core — useSWR and the Stale-While-Revalidate Pattern const {data, error, isLoading, mutate} = useSWR('/api/history', fetcher, {revalidateOnFocus: false, dedupingInterval: 60000}). A BFF solves all of these in one layer owned by the UI team. React Performance in Streaming UIs — React.memo, useRef, fast-deep-equal, Framer Motion & streamdown
Why This Day Matters A streaming LLM UI gets a state update every 50–100ms during generation. If your message list re-renders on every update, and each message re-runs markdown parsing on every token, a 20-message conversation has O(20 × 200 tokens) = 4,000 expensive markdown parses. Users see lag. The fix is understanding exactly when React re-renders and using the right primitives to prevent unnecessary work. Framer Motion handles all the animation. streamdown handles streaming-safe markdown.
WHAT YOU WILL LEARN
01
React.memo Custom Comparator — The return true/false Semantics memo(Component, comparator). The comparator receives (prevProps, nextProps) and returns: true = "these props are equal, DO NOT re-render"; false = "props changed, DO re-render". This is the OPPOSITE of JavaScript's natural "does anything differ?" — the function answers "are they the same?" not "do they differ?". Common bug: ending the comparator with return false instead of return true — the component ALWAYS re-renders (memo is disabled). Correct pattern: return !(prevProps.message.parts !== nextProps.message.parts || prevProps.isLoading !== nextProps.isLoading) or equivalently: check each inequality and return false if different, then return true at the end.
02
fast-deep-equal — When shallow comparison isn't enough import equal from 'fast-deep-equal'. Used in memo comparator for message parts: if (!equal(prevProps.message.parts, nextProps.message.parts)) return false. message.parts is an array of objects — shallow === comparison would always return false (new array object on every update). Deep equal checks structural equality. Why fast-deep-equal over lodash.isEqual: 3KB vs 70KB, 10× faster. Apply deep equal only on expensive props (arrays, objects). For primitives (string, number, boolean) use !==. For the outer messages list: !equal(prevProps.messages, nextProps.messages) — but also check messages.length first (fast bail-out).
03
useRef for Performance-Critical Non-Reactive Values The stream cursor counter in useChat must be a ref, not state: const streamCursorRef = useRef(0). Increment: streamCursorRef.current++. If it were state (useState(0)), incrementing it on every chunk would trigger a re-render on every token — defeating the experimental_throttle. Read refs synchronously in callbacks: headers: {'X-Resume-Stream-Cursor': streamCursorRef.current.toString()} — always the current value. The lastPart ref works the same way: updated in onStreamPart (sync), read in onFinish (sync) — no stale closure because refs are mutable boxes, not captured values. Pattern: use state when you need a re-render; use ref when you need the value but not the re-render.
04
Framer Motion — Streaming Animations Core patterns for streaming UIs: AnimatePresence + motion.div for enter/exit (reasoning indicator fade, scroll button): <AnimatePresence><motion.div initial={{opacity:0, y:-4}} animate={{opacity:1, y:0}} exit={{opacity:0, y:-4}} /></AnimatePresence>. streamdown — Streaming-Safe Markdown Rendering Standard markdown renderers (react-markdown) parse the full string on every render. During streaming, the text changes 10× per second — each render triggers a full parse. For 500 tokens, that is 500 full markdown parses. streamdown is designed for incremental text arrival: it renders valid HTML as tokens arrive without re-parsing the entire document. Usage: <Streamdown className="prose prose-sm dark:prose-invert max-w-none">{text}</Streamdown>. Use streamdown for the in-progress assistant message. Switch to react-markdown if you need rehype plugins (syntax highlighting) on completed messages. The switch happens naturally: after streaming completes, the message is the same component with the same text — choose the renderer that handles completed content best.

next-themes — Dark Mode System Architecture ThemeProvider from next-themes: <ThemeProvider attribute="class" defaultTheme="system" enableSystem disableTransitionOnChange>. Adds/removes the .dark class on <html>. Tailwind v4 dark mode: @custom-variant dark (&:is(.dark, .dark *)) in CSS — enables dark: utility prefix. useTheme() hook: const {theme, setTheme, resolvedTheme} = useTheme(). resolvedTheme is the actual applied theme ('light' or 'dark') accounting for system preference when theme === 'system'. Toggle: setTheme(resolvedTheme === 'dark' ? 'light' : 'dark'). Persistence: next-themes uses localStorage automatically. MutationObserver for theme-color meta tag: observe document.documentElement for class attribute changes to update the PWA theme color dynamically.

Watch Out
DataStream context causes every consumer to re-render on every chunk
The DataStreamProvider stores all reasoning-step and cache-hit events. When setDataStream(ds => [...ds, newPart]) is called in onData, every component reading useDataStream() re-renders — even components that don't care about the new event type. Fix: use useMemo inside DataStreamProvider so the context value only changes when the array reference changes: const value = useMemo(() => ({dataStream, setDataStream}), [dataStream]). Also: clear the data stream on chat ID change (useEffect(() => setDataStream([]), [id])) — otherwise reasoning steps from chat A appear on chat B.
