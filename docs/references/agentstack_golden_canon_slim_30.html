Mini Exercise

Watch Out
button vs div for click handlers: div with onclick is invisible to keyboard users and screen readers. Use button — focusable, Enter/Space triggers it, announces its role. Every interactive element in a chat UI (send, stop, delete, dropdown trigger) must be a real button or anchor. ALSO: button type gotcha — inside a <form>, any <button> without type='button' is a submit button. <button>Send</button> without type='button' triggers form submit on click, clearing the form and reloading the page. Always write: <button type='button' onClick={...}>. The chat input's send button must be type='button'. This is the #1 unexpected form submission bug in React SPAs.

Phase F2 · Day S08
Generators + Async Generators + SSE Parsing + Fetch + AbortController — CRITICAL
Source: Compresses Days 16-17-18
WHAT YOU WILL LEARN
01
Generator Functions function* gen() { yield 1; yield 2; }. g.next() → {value,done}. for...of iterates until done. Lazy — nothing executes until .next(). Infinite generators. The parseAgentSSE is an async generator that yields one parsed event per yield.
02
Async Generator SSE Parser async function* parseAgentSSE(body){const reader=body.getReader();const dec=new TextDecoder();let buf='';try{while(true){const{done,value}=await reader.read();if(done)break;buf+=dec.decode(value,{stream:true});const lines=buf.split('\n');buf=lines.pop()??'';for(const line of lines){if(!line.startsWith('data: '))continue;const p=line.slice(6).trim();if(p==='[DONE]')return;try{yield JSON.parse(p)}catch{}}}}finally{reader.releaseLock()}}
03
Fetch API fetch(url,{method,headers,body:JSON.stringify(d),signal}). response.ok before .json(). Content-Type:application/json for POST. credentials:'include' for cookies. globalThis.fetch in Node (not axios — axios buffers). response.body is ReadableStream.
04
SSE Buffer Accumulation Chunks do NOT align with SSE events. A chunk may contain half an event or multiple events. Buffer: buf+=decoded; split on '\n'; keep last incomplete line (lines.pop()); process only complete lines. Trim for \r\n. Check 'data: ' prefix before parsing.
05
AbortController + X-Accel-Buffering controller.abort('USER_CANCEL'). catch(e){if(e.name==='AbortError')return;throw e}. One controller per component mount, abort in useEffect cleanup. X-Accel-Buffering:no on every SSE response — without it NGINX/Traefik buffers everything and sends at once at end.

TextDecoder({stream:true}) vs TextDecoder(): non-stream mode treats each decode() call independently — multibyte characters split across chunks become garbage. Always use {stream:true} when decoding incrementally.

Electron Architecture — Process Model, Preload + contextBridge IPC, Security & Dev Cycle
Source: Electron Fundamentals — new content for Now & Not Now / Sage
WHAT YOU WILL LEARN
01
The Two-Process Mental Model — Main vs Renderer Electron has two distinct JavaScript environments that can never call each other directly. Main process: runs in Node.js, full OS access (filesystem, spawn, native modules), one instance per app, creates BrowserWindows, manages Tray, handles app lifecycle. Renderer process: runs in Chromium, renders HTML/CSS/React, sandboxed by default (no Node.js APIs). Multiple renderer processes can exist (one per BrowserWindow). The Now & Not Now app has: one main process, one tray window renderer, one ribbon window renderer. Rule: all OS work in main, all UI in renderer. Never cross the boundary directly.
02
Preload Script + contextBridge — The Secure Bridge The preload script runs in a privileged context with access to both Node.js and the DOM — but it executes before the renderer page loads. contextBridge.exposeInMainWorld('sage', { invoke: (channel, ...args) => ipcRenderer.invoke(channel, ...args), on: (channel, callback) => { const sub = (_e, ...args) => callback(...args); ipcRenderer.on(channel, sub); return () => ipcRenderer.removeListener(channel, sub) } }). This is the ONLY way renderer code can call main. In the renderer: window.sage.invoke('sidecar:status'). Never expose ipcRenderer directly — attackers in the renderer could then call any channel. Allowlist channels in preload.
03
ipcMain.handle + ipcRenderer.invoke — Request-Response IPC In main: ipcMain.handle('sidecar:status', async () => { return { pid: sidecarPid, port: sidecarPort, alive: isAlive } }). ipcMain.handle returns a Promise — the return value is automatically sent back to the invoker. In preload: ipcRenderer.invoke('sidecar:status') returns a Promise<T>. In renderer: const status = await window.sage.invoke('sidecar:status'). Errors thrown in the handler are serialised and re-thrown in the renderer. For push events (main → renderer): ipcMain.emit does NOT work. Use: win.webContents.send('sidecar:crashed', { exitCode }). In preload: ipcRenderer.on('sidecar:crashed', callback). For cleanup: always return the unsubscribe function from ipcRenderer.on wrappers.
04
Security Model — nodeIntegration off, contextIsolation on BrowserWindow config: new BrowserWindow({ webPreferences: { preload: path.join(__dirname, 'preload.js'), nodeIntegration: false, contextIsolation: true, sandbox: true } }). nodeIntegration: false — renderer cannot require() Node modules. contextIsolation: true — preload and renderer run in separate JS worlds (different globals, no prototype pollution). sandbox: true — renderer is fully OS-sandboxed (recommended for production). webSecurity: true (never set false — disables same-origin policy). CSP header in the HTML: Content-Security-Policy: default-src 'self'; script-src 'self'. Why: if an attacker injects JS into your renderer (XSS), with nodeIntegration:true they get full OS access. With isolation:true they can only call what you explicitly expose via contextBridge.
05
Dev Cycle — electron-vite + HMR for Renderer + nodemon for Main electron-vite (npm package): unified config handles both main and renderer builds. vite.config.ts: defineConfig({ main: { entry: 'src/main/index.ts' }, preload: { input: 'src/preload/index.ts' }, renderer: { /* standard Vite config */ } }). Dev command: electron-vite dev — starts Vite dev server for renderer (HMR on save), watches and rebuilds main, restarts Electron on main changes. Equivalent manual setup: nodemon for main process rebuilds + Vite dev server for renderer, with electron started via script pointing main to Vite server URL. __dirname in packaged app: use app.isPackaged ? path.join(process.resourcesPath, 'app') : path.join(__dirname, '../..'). Health Probe Loop — Wait for Sidecar Before Showing UI async function waitForSidecar(port, timeoutMs = 15000): { const deadline = Date.now() + timeoutMs; while (Date.now() < deadline) { try { const res = await fetch(`http://localhost:${port}/health`, {signal: AbortSignal.timeout(1000)}); if (res.ok) return true } catch {} await sleep(300) } throw new Error('Sidecar health timeout') }. 05
Crash Recovery — Exponential Backoff Restart let restartAttempts = 0; const MAX_RESTARTS = 5. function handleSidecarExit(code, signal) { if (isQuitting) return; if (code === 0) return; restartAttempts++; if (restartAttempts > MAX_RESTARTS) { win.webContents.send('sidecar:fatal'); return } const delay = Math.min(1000 * 2 ** restartAttempts, 30000); log.warn(`Sidecar crashed (code ${code}), restarting in ${delay}ms (attempt ${restartAttempts})`); setTimeout(()=>startSidecar(), delay); }. Reset restartAttempts = 0 on successful health probe. Notify renderer on crash: win.webContents.send('sidecar:crashed', { exitCode: code, attempt: restartAttempts }). Renderer shows a degraded state UI while restarting. On FATAL: show 'Sage is having trouble starting' with a Restart button that calls window.sage.invoke('app:restartSidecar').

In FastAPI sidecar: @app.post('/shutdown') async def shutdown() => { asyncio.get_event_loop().call_later(0.1, sys.exit, 0) ; return {'ok': True} }.

In Electron: fonts are local — should load instantly, but asar packaging can cause a flash. Solutions: (1) Use system fonts: font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif — no loading. (2) Bundle OFL fonts as Base64 in CSS: @font-face { src: url('data:font/woff2;base64,...') } — zero network request. (3) Use Electron's protocol to serve fonts: protocol.registerFileProtocol('font', handler) — faster than file:// for asar. (4) Preload fonts: <link rel='preload' as='font' href='...' crossorigin> in the HTML head. For Now & Not Now: use Berkeley Mono (OFL) or Geist (OFL) — both can be bundled. Always specify font-display: block for the composer (text must never be invisible during typing).

Hairline Borders + No-Shadow Visual Language Hairline borders: 1px solid var(--border) — but on Retina displays, 1px CSS = 2 physical pixels. True hairline: transform: scaleY(0.5) on a pseudo-element, or border: 0.5px solid (Safari/macOS only). Consistent approach: use border-image with a 1px solid at device pixel ratio — complex. Practical: accept 1px CSS border (2px physical on Retina) for simplicity. No-shadow language: avoid box-shadow on cards and panels — use border and subtle background-color changes instead. Exceptions: the main tray window itself (drop shadow) and the 'now' task highlight (very subtle inset shadow). Background elevation: --surface: hsl(0 0% 100%), --surface-elevated: hsl(0 0% 97%), --surface-raised: hsl(0 0% 94%) — subtle lightness steps, no shadows. On dark: reverse the steps (darker elevated surfaces).

Streaming Token Rendering from Local SSE (Sage AI Response) The Sage AI response streams from the local Python sidecar via SSE — same EventSource/fetch streaming pattern as web, but the URL is localhost. const es = new EventSource(`http://localhost:${port}/sage/stream?query=${encodeURIComponent(query)}`). es.onmessage = e => appendToken(JSON.parse(e.data).token). es.onerror = ()=>handleError(). Or: fetch streaming (POST body): the Sage composer sends a POST to the sidecar, reads the SSE response stream with the same parseAgentSSE async generator pattern from Day S08. In Electron renderer: no CORS restrictions for localhost — the renderer has same-origin access. Streaming markdown: use streamdown (from Day S26). The token buffer accumulates in the Ribbon item; the item height expands smoothly with CSS transition: height 150ms ease.

WHAT YOU WILL LEARN
01
Manifest V3 Fundamentals — Service Worker, Permissions, Content Scripts manifest.json: { "manifest_version": 3, "name": "Now & Not Now", "version": "1.0", "permissions": ["storage", "activeTab", "scripting"], "host_permissions": ["http://localhost/*"], "background": { "service_worker": "background.js", "type": "module" }, "action": { "default_popup": "popup.html", "default_icon": "icon-128.png" }, "content_scripts": [{"matches":["<all_urls>"],"js":["content.js"],"run_at":"document_idle"}] }. Key MV3 changes from MV2: background pages → service worker (no persistent state, wakes on events). XMLHttpRequest → fetch only. Remote code execution blocked. host_permissions separate from permissions. Service workers terminate after 30s inactivity — store state in chrome.storage.local not memory variables.
02
Message Passing to Localhost — Extension ↔ Sidecar Extension to localhost: host_permissions: ["http://localhost/*"] enables fetch to localhost. In background service worker: fetch('http://localhost:PORT/capture', {method:'POST', body: JSON.stringify(data)}). Content script to background: chrome.runtime.sendMessage({type:'CAPTURE_TASK', data}). Background receives: chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => { if(msg.type==='CAPTURE_TASK'){fetch(sidecarUrl,...).then(r=>r.json()).then(sendResponse);return true} }). return true: keeps the message channel open for async sendResponse. Port discovery challenge: the extension doesn't know which port the sidecar is on. Solution: sidecar writes port to a known file AND to a local HTTP endpoint; OR extension reads from chrome.storage.local where the Electron app writes the port via a shared mechanism (localhost polling or a well-known fixed port for the extension bridge).
03
Handshake at Install Time — Extension Detects Sidecar chrome.runtime.onInstalled.addListener(async (details) => { if(details.reason === 'install') { const isAlive = await checkSidecar(); if(!isAlive) { chrome.action.setBadgeText({text:'!'}); chrome.action.setBadgeBackgroundColor({color:'#ef4444'}) } } }). checkSidecar: try GET http://localhost:KNOWN_PORT/health → ok. If sidecar is not running: popup shows 'Please open Now & Not Now first'. Extension stores the port in chrome.storage.local. Electron side: on app start, write the port to a local HTTP endpoint or a fixed file that the extension can read. Bidirectional: extension can send captured tasks to sidecar; sidecar can push context to extension via polling (extension polls sidecar every 30s for context updates like 'you have a meeting in 5 min').
04
WebExtensions Polyfill — Firefox + Safari Support Chrome uses chrome.* APIs; Firefox uses browser.* APIs (Promise-based); Safari uses browser.* APIs. webextension-polyfill (npm): wraps chrome.* into browser.* with Promises. import browser from 'webextension-polyfill'. browser.runtime.sendMessage(...) returns Promise — no callback pattern needed. bundle: webpack/Rollup bundles the polyfill into background.js and content.js. For Now & Not Now extension: target Chrome + Safari (macOS users likely on Safari). Safari Web Extensions: convert with xcrun safari-web-extension-converter. Requires a Safari Extension app wrapper (macOS/iOS app). Distribution: Safari Extension via Mac App Store, not a .crx file. Key limitation: Firefox blocks localhost requests from extensions by default in some configs (user must set network.websocket.allowInsecureFromHTTPS in about:config) — document this clearly.
05
Renderer-Side States When Sidecar Crashes or Ollama Is Down Two independent failure modes: sidecar down (Python process crashed — no API at all) and Ollama down (sidecar is running but LLM calls fail — partial degradation). Sidecar down states: (1) Starting: pulsing indicator 'Sage is starting...'. (2) Crashed (recovery in progress): 'Sage encountered an issue — restarting (attempt N/5)', show last-known tasks from local cache. (3) Fatal: 'Sage failed to start — Restart App' button. Ollama down states: (1) Detected: sidecar health includes ollama_available:false. Renderer shows: 'AI responses unavailable — tasks still work'. (2) Core task management (add/complete/reschedule) works without Ollama. (3) Sage AI chat box: grayed out with tooltip 'Ollama not running — start Ollama to enable AI'. Key principle: never show a blank/loading screen for a crash — always show last-known state with an error overlay.
06
User-Visible Degradation Patterns — Graceful Feature Gating Map each feature to its dependency: Task management (core) → no dependencies. AI chat (Sage) → sidecar + Ollama. Calendar context → Calendar permission + sidecar. Triple-tap shortcut → Accessibility permission + uIOhook. Browser capture → Extension installed. Degradation matrix: useFeatureStatus() hook reads from context; each feature renders its enabled/degraded/unavailable variant. Degraded: show feature but with reduced capability (e.g., show tasks without AI enhancement). Unavailable: hide or gray out with a clear explanation. Never show a generic error — always name the specific missing dependency and how to fix it. Toast pattern: 'Ollama is not running — [Start Ollama] [Dismiss]'. The [Start Ollama] button: shell.openExternal('http://localhost:11434') or attempt to launch Ollama via spawn if installed.
Mini Exercise
Build the complete error resilience layer: (1) useSystemStatus() hook: polls ipcRenderer.invoke('system:status') every 5s → { sidecarAlive, sidecarRestartCount, ollamaAlive, calendarGranted, accessibilityGranted, extensionInstalled }; (2) StatusProvider wraps the app, exposes useSystemStatus(); (3) SidecarStatusBanner: 'starting' (pulsing) / 'crashed attempt N/5' (yellow) / 'fatal' (red + restart button); (4) OllamaBanner: shown when sidecarAlive but !ollamaAlive — 'AI unavailable — [Start Ollama]'; (5) SageComposer: disabled with tooltip when !ollamaAlive; (6) Browser extension: manifest.json + background.js that polls sidecar health on install, shows badge '!' when sidecar not found, clears on sidecar detected; (7) WebExtension polyfill — use browser.* everywhere.
Watch Out
MV3 service workers do not persist. Variables reset between events: if you store the sidecar port in a module-level variable in background.js, it will be undefined after the service worker restarts (which happens frequently — Chrome may restart it after 30 seconds of inactivity, or on browser restart). Always persist critical state to chrome.storage.local: await chrome.storage.local.set({sidecarPort: port}). Read it back: const {sidecarPort} = await chrome.storage.local.get('sidecarPort'). This also means MV3 extensions cannot hold a persistent WebSocket connection — use polling from the service worker (setInterval does NOT persist through service worker restarts — use chrome.alarms.create for recurring background tasks).
